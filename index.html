Troubleshooting & Optimization

1. 배치 스케줄러 스레드 폭증 OOM 대응

AS-IS (Problem)

작업마다 스레드를 무분별하게 새로 생성하여 스레드 10,000개 폭증 및 OutOfMemoryError 발생

TO-BE (Solution)

  • - 공통 ThreadPoolExecutor 구현으로 최대 가동량 제어
  • - LinkedBlockingQueue 도입으로 Back-pressure 조절
  • - SimpleJdbcInsert 객체 재사용으로 GC 부하 감소

Result: OOM 장애 발생 건수 0 달성

2. JVM GCLocker 활성화로 인한 GC 불가 상태 해결

AS-IS (Problem)

특정 시점부터 Heap OutOfMemoryError(OOM) 문제가 발생하여 서버가 다운되는 현상이 발생

What I Did (Approach)

- 시스템 로그상 원인 파악이 제대로 진행되지 않아 OOM이 발생했을 때, Heap dump를 사용하여 메모리에서 어떠한 문제가 있는지 파악

- Heap Dump 결과에서도 할당한 메모리보다 훨씬 작은 메모리만 사용하는 것으로 보아 다른부분에서 문제가 발생한 것으로 예상되어 의심이되는 코드 및 GC logs 추가 확인

- 확인 결과 UNION ALL을 통한 대규모 INSERT가 JNI 호출을 통해 실행되면서 GCLocker가 작동이 되면서 강제로 메모리 회수가 지연되며 힙 공간이 고갈되어 OOM이 문제가 된것을 확인

TO-BE (Solution)

  • - Bulk Insert 전략 수정: UNION ALL 방식 대신 파티셔닝된 Batch Insert 도입
  • - JNI 점유 시간 최소화: DB 드라이버 설정 및 쿼리 최적화로 Critical Section 체류 시간 단축
  • - JVM 파라미터 튜닝: GCLocker 발생 시 대응을 위한 대기 스레드 정책 검토

Result: OOM 장애 발생 건수 0 달성
